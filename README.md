# li 语言编译器

li 是一门面向专业开发者的通用编程语言，使用中文关键字与中文符号，同时兼容英文写法。
编译器采用**前端统一、IR 中立、多后端**的架构，当前已实现：

- 词法分析、语法分析与语义分析；
- 严格编译期检查：不可变变量重赋值、可选值未判空、结果值未匹配、禁止隐式类型转换；
- 保留类型信息的中立 IR，使用三地址码与控制流图（CFG）；
- JavaScript 后端，可把 `.li` 编译为 Node.js 可直接运行的 `.js`；
- 字节码后端与栈式虚拟机，可把 `.li` 编译为便于阅读的 `.lic` 文本并执行；
- 文本 LLVM IR 后端骨架，可生成 `.ll` 并交由 `clang` 构建原生程序；
- 标准库基础能力：字符串、列表、字典与文件读写；
- `不安全` 块与 `原生指针<T>`，把底层内存操作隔离在显式边界内；
- `.lui` 视图文件与静态 HTML 后端，可把中文界面声明导出为标准 HTML5；
- 项目级配置 `li.toml`、依赖锁 `li.lock`、`li 获取` 与跨包 `导入`，支持本地路径和 Git 依赖。

## 使用

把 li 源码编译为字节码并交给虚拟机执行：

```bash
cargo run -p li-cli -- 编译 crates/li-parser/tests/fixtures/fibonacci.li
cargo run -p li-cli -- 执行 crates/li-parser/tests/fixtures/fibonacci.lic
# 输出：55
```

也可以把 li 源码编译为同名 JavaScript 文件：

```bash
cargo run -p li-cli -- 编译-js 示例.li
node 示例.js
```

`打印(值)` 在 JavaScript 后端映射为 `console.log(__li_显示(值))`，
由统一显示函数处理 `真` / `假` / `空`、列表与字典的格式；在字节码后端
映射为 `PRINT` 指令并由虚拟机输出到控制台。

也可以生成文本 LLVM IR，再交给本机的 `clang` 构建原生可执行文件：

```bash
cargo run -p li-cli -- 编译-llvm 示例.li
clang -O2 示例.ll -o 示例
./示例
```

生成 `.ll` 不依赖本机安装 LLVM；只有构建原生二进制时才需要 `clang` 或 `llc`。

也可以一步完成“生成 IR + 链接原生 ELF”：

```bash
cargo run -p li-cli -- 编译-原生 示例.li
./示例
```

交叉编译到 ARM64 并静态链接，产物不依赖目标机的动态库：

```bash
cargo run -p li-cli -- 编译-原生 示例.li --target aarch64-linux-gnu
file 示例.aarch64-linux-gnu
# ELF 64-bit LSB executable, ARM aarch64, ... statically linked
```

指定 `--target` 时，li 会把目标三元组写入 LLVM 模块的 `target triple`，
并自动追加 `-static`；未指定时使用宿主默认目标。

### Termux / Android 兼容性说明

`--target aarch64-linux-gnu` 生成的是 **Linux/glibc 静态 ELF**，不是 Android/bionic
可执行文件。静态链接消除了对 `libc.so` 的运行期依赖，因此通常可以直接拷贝到
Termux 执行；注意 `/sdcard` 一般以 `noexec` 挂载，请放在 `$HOME` 等可执行目录。

两者仍有差异：bionic 与 glibc 在 NSS、`/etc/passwd`、时区数据库与部分 syscall
包装上并不一致，依赖用户名解析、系统时区或系统 DNS 配置的程序可能需要调整。
若需要真正的 Android 原生程序，请安装 Android NDK 并使用 Android 目标：

```bash
export ANDROID_NDK_ROOT=$HOME/android-ndk-r26d
export PATH=$ANDROID_NDK_ROOT/toolchains/llvm/prebuilt/linux-x86_64/bin:$PATH
li 编译-原生 示例.li --target aarch64-linux-android
```

未检测到 NDK 时，`li 编译-原生` 会在调用 clang 之前给出中文指引并退出，
而不是把 clang 的英文报错直接抛给用户。

## 项目配置与依赖

项目根目录的 `li.toml` 声明项目信息与依赖：

```toml
[项目]
名称 = "示例"
版本 = "0.1.0"
入口 = "主.li"

[依赖]
数学库 = { 路径 = "../数学库" }
网络库 = { git = "https://example.com/net.git", 版本 = "v1.0" }
```

运行 `li 获取` 会把依赖复制到 `.li/依赖/` 并生成 `li.lock`，Git 依赖会记录精确提交：

```bash
cargo run -p li-cli -- 获取
cargo run -p li-cli -- 运行
```

主程序通过 `导入 数学库;` 使用外部包，并以 `数学库.加法(1, 2)` 调用其函数。
包内入口优先读取它自己的 `li.toml` 中 `[项目].入口`，否则探测 `主.li`、
`src/主.li`、`lib.li`、`src/lib.li` 等常见布局。`li 运行` 省略文件参数时，
会从当前目录向上查找 `li.toml` 并使用项目入口；编译前会检查锁文件与依赖目录是否就绪。

## `.lui` 视图文件与 HTML 导出

`.lui` 文件使用声明式的 `视图 { ... }` 语法描述页面结构。字符串仍然严格使用
中文书名号 `「」` 定界，例如：

```lui
# 你好.lui
视图 {
    标题: 「你好，li」,
    容器 {
        标题 { 文本 { 「你好，li！」 } }
        段落 { 文本 { 「这是由 li 编译器生成的静态页面。」 } }
        按钮 { 类: 「主按钮」, 类型: 「button」, 文本 { 「点我」 } }
    }
}
```

通过 CLI 导出静态 HTML：

```bash
cargo run -p li-cli -- 编译-html 你好.lui
# 已生成 HTML：你好.html
```

生成结果是一个完整的 HTML5 文档：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>你好，li</title>
</head>
<body>
    <div>
        <h1>你好，li！</h1>
        <p>这是由 li 编译器生成的静态页面。</p>
        <button class="主按钮" type="button">点我</button>
    </div>
</body>
</html>
```

常用映射包括 `容器` → `div`、`标题` → `h1`、`段落` → `p`、`按钮` → `button`、
`文本` → 纯文本，以及 `类` → `class`、`标识` → `id`、`链接` → `href`、
`类型` → `type` 等属性。也可以直接使用常见的 ASCII 静态 HTML 标签名与属性名；
`script`、`style` 等标签与 `on*` 事件属性会被明确拒绝。

### 单体交互视图

视图可以直接声明状态、事件与绑定，编译结果仍然是**一个** HTML 文件：

```lui
视图 {
    标题: 「计数器」,
    状态 { 让 可变 次数 = 0; }
    容器 {
        文本 { 「当前计数：」, 次数 }
        按钮 {
            点击 { 次数 = 次数 加 1; }
            文本 { 「加一」 }
        }
    }
}
```

- `状态 { ... }` 只允许出现在视图根节点，内部只能写变量声明；
- `点击`、`双击`、`输入`、`改变`、`提交`、`聚焦`、`失焦`、`按下`、`松开`、
  `鼠标进入`、`鼠标离开` 会映射为标准 DOM 事件；
- `文本 { 「计数：」, 次数 }` 与 `隐藏: { 次数 等于 0 }` 注册渲染绑定，
  事件执行后自动重新渲染；
- 交互代码支持字面量、变量、运算、`打印`、`如果`、`当`、`跳出`、`继续`；
  其他结构会在编译期给出带行列号的中文诊断。

产物不生成 `app.js`、不引用外部 CSS 或脚本，浏览器直接打开即可交互。
还可以把单体产物放在内存中直接提供 HTTP 服务，不落地任何静态文件：

```bash
cargo run -p li-cli -- 服务 计数器.lui 8080
# 服务已启动：http://127.0.0.1:8080/
```

`li 服务` 接受任意 `.lui` 文件与可选端口（默认 8080），`GET /` 返回单体
HTML，其他路径返回中文 404。

视图根节点支持 `标题`、`语言`、`描述` 三个文档属性。未映射的中文标签或属性
会在编译期报出带行列号的中文错误；`图片`、`输入框`、`换行`、`分隔线`
等空元素不能包含子节点。

## 字节码与虚拟机

`li-codegen-bytecode` 把中立 IR 的 CFG 展开为线性指令序列，并把基本块标签
回填为函数内的指令地址。指令集包括：

```text
PUSH_CONST  LOAD  STORE  POP  ADD  SUB  MUL  DIV  NEG  NOT
LT  GT  EQ  AND  OR  JUMP  JUMP_IF_FALSE  CALL  RETURN  RETURN_VOID
HALT  PRINT  INPUT  MAKE_LIST  GET_FIELD  SET_FIELD  GET_INDEX  SET_INDEX
WRAP_OPTIONAL  WRAP_RESULT  IS_SUCCESS  UNWRAP  UNWRAP_ERROR  NOP
```

每个函数拥有常量池引用、局部槽位表与独立的操作数栈；`CALL` 创建新的调用帧，
`RETURN` 把返回值送回调用者。`.lic` 使用文本格式，跳转目标直接写成指令下标，
每条指令末尾的 `@行:列` 指向对应的 li 源码位置，便于调试运行时错误。

斐波那契函数生成的字节码片段：

```text
.constants 4
0 整数 2
1 整数 1
2 整数 10
3 整数 0
.end

.function 斐波那契 1
.slots 项数 t0 t1 t2 t3 t4 t5
.code
0000 LOAD 0 @3:8
0001 PUSH_CONST 0 @3:8
0002 LT @3:8
0003 STORE 1 @3:8
0004 LOAD 1 @3:5
0005 JUMP_IF_FALSE 9 @3:5
0006 JUMP 7 @3:5
0007 LOAD 0 @4:9
0008 RETURN @4:9
...
.end
```

虚拟机运行时会重新校验常量下标、槽位下标、跳转目标与函数调用，并用
`第 N 行第 M 列：运行时错误：...；函数「...」，指令 ...` 的格式报告错误。

## 标准库基础能力

字符串按 Unicode 字符计数与切片，`切片(起, 止)` 使用左闭右开区间，
越界自动钳制，起止倒置返回空串。`分割("")` 按字符拆分。

| 字符串方法 | 签名 | 说明 |
| --- | --- | --- |
| `长度()` | `整数` | Unicode 字符数量 |
| `拼接(后缀)` | `字符串` | 连接两个字符串 |
| `转整数()` | `结果<整数, 字符串>` | 失败时返回中文错误说明 |
| `包含(子串)` | `布尔` | 是否包含子串 |
| `字符(下标)` | `可选<字符串>` | 越界或负下标返回空 |
| `切片(起, 止)` | `字符串` | 左闭右开，按字符切片 |
| `查找(子串)` | `可选<整数>` | 返回字符下标 |
| `替换(旧, 新)` | `字符串` | 替换全部匹配 |
| `分割(分隔符)` | `列表<字符串>` | 空分隔符按字符拆分 |

| 列表方法 | 签名 | 说明 |
| --- | --- | --- |
| `长度()` | `整数` | 元素数量 |
| `添加(值)` | `列表<T>` | 追加并返回列表自身 |
| `获取(下标)` | `可选<T>` | 越界或负下标返回空 |
| `删除(下标)` | `布尔` | 越界或负下标返回 `假` |

| 字典方法 | 签名 | 说明 |
| --- | --- | --- |
| `长度()` | `整数` | 键值对数量 |
| `插入(键, 值)` | `字典<K, V>` | 已存在的键只更新值 |
| `获取(键)` | `可选<V>` | 键不存在时返回空 |
| `删除(键)` | `布尔` | 键不存在时返回 `假` |
| `包含键(键)` | `布尔` | 是否包含指定键 |

字典键只允许 `字符串`、`整数`、`小数` 与 `布尔`，且必须通过 `匹配`

```li

电话簿 = 电话簿.插入(「小明」, 「123」);
```

| `新建字典()` | `字典<K, V>` | 需要显式目标类型 |

| 模块函数 | 签名 | 说明 |
| --- | --- | --- |
| `系统.时间戳()` | `整数` | 当前 UNIX 时间戳（秒） |
| `系统.获取参数()` | `列表<字符串>` | 进程命令行参数 |
| `系统.获取环境变量(键)` | `可选<字符串>` | 环境变量缺失时为空 |
| `正则.匹配(文本, 模式)` | `布尔` | 是否匹配正则模式 |
| `正则.替换(文本, 模式, 替换内容)` | `字符串` | 全局替换所有匹配 |

## 枚举与穷尽匹配

li 支持带载荷的枚举类型，用 `枚举 名称 { 枚举项(载荷类型), ... }` 声明；
`匹配` 必须覆盖每个枚举项，缺项会报红色 `匹配缺少枚举项「...」分支` 错误，
编译被拦截。

```li
枚举 节点 {
    数字,
    加法,
    无值,
}

函数 求值(节点: 节点, 左: 整数, 右: 整数) -> 整数 {
    匹配 节点 {
        枚举项 数字 => { 返回 左; },
        枚举项 加法 => { 返回 左 + 右; },
        枚举项 无值 => { 返回 0; },
    }
    返回 0;
}
```

- 构造器语法是 `类型::项名(载荷...)`，由解析器在 `::` 后捕获左侧枚举
  类型名；`枚举项 名称(载荷绑定)` 是匹配模式的写法；
- 枚举项按声明顺序索引，索引即判别符；纯标签枚举在 LLVM 后端可直接
  降级为 `i64` 判别符并参与比较、分支；
- 带载荷的枚举在 VM / JS 后端目前仍按"判别符 + 实参顺序求值"处理，
  载荷解构尚未进入 IR，由语义分析器对载荷绑定给出黄色警告；
- 带堆数据的复杂枚举（例如 `圆(整数)`、`方(整数)`）在 LLVM 后端会输出
  黄色警告「LLVM 后端暂只支持纯标签枚举；若该枚举携带堆数据，运行期
  行为未定义；建议改用 VM 或 JS 后端编译」，编译放行、产物正常生成。

## 二进制瘦身与 `--release`

`li 编译-原生 <文件.li> [--target <三元组>] [--release]`：

- 默认（调试模式）：使用 `clang -O2` 链接；
- `--release`：使用 `-Os` 空间优化，追加 `-ffunction-sections`
  `-fdata-sections` 与 `-Wl,--gc-sections` 让链接器裁剪未引用函数/数据，
  并用 `-Wl,-s` 剥离符号表；
- `--target` 与 `--release` 可以任意顺序组合；
- 实测：同一份纯标签枚举演示程序在 debug 下约 16 KB，在 release
  下约 14 KB；`-static` 全静态链接约 700 KB，默认不启用，需要时由
  用户显式追加。

## `#无垃圾回收` 与 no_std

在文件最前端写 `#无垃圾回收` 指令，可启用 no_std 模式：

```li
#无垃圾回收
函数 主() -> 整数 {
    让 数值: 整数 = 42;
    打印(数值);
    返回 0;
}
```

- 该指令只能出现在文件最前端、任何程序项之前；重复声明、或出现在
  程序项之后都会报红色错误；
- 指令会被词法、语法、语义分析、IR 各阶段传递，LLVM 后端据此
  决定是否引入 GC 运行时；
- 在 no_std 模式下，使用 `字符串`、`列表`、`字典` 类型（包括
  类型标注、字符串字面量、列表字面量）会输出黄色警告，提示这些
  类型依赖堆分配，建议改用 `原生指针` 与 `不安全` 块手动管理
  内存；编译继续、产物正常生成；
- 该指令与 `不安全` 块互补：`#无垃圾回收` 声明目标不依赖 GC，
  `不安全 { ... }` 是真正操作底层内存的必需包裹。

## 不安全块与原生指针

默认代码始终处于安全检查之下。裸指针类型、指针值的使用以及未来的
手动内存操作必须包裹在 `不安全 { ... }` 中：

```li
函数 空指针() -> 原生指针<整数> {
    不安全 {
        返回 空;
    }
}

函数 主() -> 整数 {
    不安全 {
        让 指针: 原生指针<整数> = 空指针();
        打印(指针 等于 空);
    }
    返回 0;
}
```

当前规则：

- 原生指针可以出现在函数签名中，但安全代码不得声明指针局部变量，
  也不得使用指针值；
- `空` 可以作为原生指针的空值；
- VM 以空指针占位值执行当前 M11 子集；JS 后端会直接拒绝程序并返回
  “当前目标平台不支持底层内存操作”；
- 分配、释放、解引用与指针算术尚未暴露为内置操作，属于后续里程碑；
  `异步`、`等待`、`通道<T>`、`共享<T>`、`借用<T>` 关键字已预留，解析与
  运行时语义尚未实现。

## 外部函数与 C-ABI 互操作

`外部 函数` 声明一个由 C 动态链接库（如 libc）提供的函数，让 li 与
现有 C 生态直接互通：

```li
# 调用 libc 的 putchar 输出字符
外部 函数 putchar(字符: 整数) -> 整数;

函数 主() -> 整数 {
    让 甲: 整数 = putchar(72);
    让 乙: 整数 = putchar(105);
    putchar(10);
    返回 0;
}
```

- 语法为 `外部 函数 名称(参数) -> 返回类型;`，没有函数体；
- 语义分析会为外部函数登记签名，因此可以正常参与调用类型检查，
  同时输出一条黄色警告，提示外部函数依赖原生链接；
- LLVM 后端据 `is_extern` 生成 `declare` 指令，链接期由系统 C 库
  提供实现；`li 编译-原生` 可直接产出可执行文件；
- VM 与 JS 后端无法在运行时绑定动态链接库，遇到外部函数会输出
  中文致命错误并拦截，并提示改用 `li 编译-原生`；
- **外部函数名必须是真实的 C 符号名**（如 `putchar`、`abs`），
  使用中文名会在链接期出现 `undefined reference`；
- 参数与返回类型当前支持 `整数`、`小数`、`布尔`、原生指针等可映射
  到 LLVM 基础类型的子集；`字符串` 与结构体跨 ABI 传递仍在规划中。

## 内联汇编（预留）

`内联汇编` 是**预留关键字**，词法与语法阶段已可识别，但当前后端尚未实现：

```li
函数 主() -> 整数 {
    内联汇编「mov eax, 1」;
    返回 0;
}
```

- 语法为 `内联汇编「模板文本」;`，模板文本是字符串字面量；
- 语义分析阶段输出红色致命错误「内联汇编 暂未实现」，并拦截编译；
  IR 降级阶段还有一次兜底拦截，确保绕过 Sema 时也不会静默生成错误代码；
- 视图交互代码同样拒绝该语句，输出中文错误；
- 该关键字的存在保证语法先行、后端后补：后续里程碑在 LLVM 后端接入
  真实内联汇编时，只需放开语义与 IR 拦截即可。

## LLVM 文本后端

`li-codegen-llvm` 直接消费中立 IR，生成可读的文本 LLVM IR（`.ll`），
不依赖 `inkwell` 或 `llvm-config`。当前覆盖：

- `整数`、`小数`、`布尔`、`字符串` 与 `原生指针<T>`；
- 枚举类型：纯标签枚举降级为 `i64` 判别符，匹配按索引分支；带
  堆数据的枚举由 `generate_reporting` 输出黄色警告并继续放行；
- 算术、比较、逻辑运算与函数调用；
- 基本块、条件分支、无条件跳转与返回；
- `打印` 映射到 `printf`，布尔值输出为 `真` / `假`。

列表、字典、可选值、结果值与内置方法需要 GC 运行时对象，当前会给出
带行列号的中文“暂不支持”诊断，而不会生成错误的本机代码。生成的 `.ll`
可由 `clang` 或 `llc` 继续编译；原生运行时的完整对象模型仍在规划中。

## 中立 IR

`li-ir` 把 AST 降级为与后端无关的中间表示：

- 数据流使用三地址码，每条指令显式保留结果类型；
- 控制流使用基本块与 CFG；
- `如果`、`当`、`跳出`、`继续`、`返回` 会转换为
  `LABEL`、`JUMP`、`BRANCH`、`RETURN` 等显式控制流指令；
- `可选<T>` 与 `结果<T, E>` 使用独立的包装/解包指令，保证后端能正确处理匹配；
- JavaScript、字节码与 LLVM 后端只消费 IR，不反向依赖 AST；
- HTML 后端是视图专用后端，直接消费 `.lui` 视图 AST，不参与可执行代码流水线。

## 统一诊断格式

`li-errors` 提供带行列号的中文诊断，例如：

```text
第 3 行第 5 列：类型不匹配，期望 整数，实际 字符串
```

错误信息同时支持期望值、实际值、稳定错误码和附注，词法、语法、语义与降级阶段共用
`Diagnostic` 与 `DiagnosticBag`。所有用户可见错误均为简体中文。
